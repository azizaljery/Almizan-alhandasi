## 4. إثبات هوية النسخة الحية

هوية النسخة المنشورة شرط إلزامي ولا يجوز الاعتماد على الاستدلال التقريبي.

يجب أن توفر النسخة الحية وسيلة موثوقة لعرض Commit SHA، مثل:

- meta tag داخل التطبيق.
- endpoint خاص بمعلومات الإصدار.
- build metadata موثوقة.

بعد النشر:

- [ ] قراءة Commit SHA من النسخة الحية.
- [ ] مقارنته حرفيًا بالـ Commit SHA المثبت قبل النشر.

### القرار

إذا:

`LIVE_SHA == APPROVED_SHA`

يستمر التحقق.

إذا:

`LIVE_SHA != APPROVED_SHA`

فالنتيجة:

`BLOCKED_VERSION_MISMATCH`

ويبدأ Rollback إذا كانت نسخة غير معتمدة قد أصبحت النسخة الحية.

عدم القدرة على إثبات SHA الحي يمنع منح PASS.

## 8. تعريف الخطأ الحرج

لأغراض هذه الخطة، يعتبر الخطأ **Critical** عند تحقق أي من الآتي:

- JavaScript exception غير معالج يؤثر في تدفق المستخدم.
- استجابة HTTP `5xx` في طلب أساسي.
- فشل طلب التوليد.
- توقف واجهة 2D أو 3D عن العمل.
- فشل BOQ في التحميل أو الإنشاء.
- فشل Save أو Restore.
- فقدان بيانات المشروع بعد Refresh.
- Crash أو شاشة غير قابلة للاستخدام.
- نجاح زائف يظهر للمستخدم رغم فشل العملية الفعلية.
- عدم تطابق النسخة الحية مع Commit المعتمد.

وجود Critical Error يمنع PASS.

- أي تعديل على شروط PASS / FAIL / BLOCKED بعد بدء التحقق يجب أن يظهر في Commit مستقل ومراجع.

بعد حفظ هذا الملف، الخطوة الصحيحة مباشرة هي مراجعة `git diff` والتأكد أن الفرع يحتوي على **هذا الملف فقط** قبل الانتقال إلى Commit إصلاح 005 نفسه.
