# متطلبات التكامل — محرك التخطيط v2 ← طبقة العرض

الحالة: **مسودة للمراجعة. لا يُنفَّذ أي منها قبل الاعتماد وتحديد المسؤول.**
المُعِدّ: نطاق المحرك (Geometry / Validation / Tests).
المستهلك: نطاق UI / 2D / 3D / Visualization.

## ملاحظة على التسمية
الحقول أدناه مأخوذة من مخرجات `generateModel()` الحالية. لم أطّلع على تعريف `ValidatedDesignGeometry` المعتمد، لذلك كل حقل مذكور باسمه الحالي، ويلزم ربطه بالاسم المقابل في الـContract عند اعتماده.

## IR-1 — اختيار شكل الكتلة

| البند | التفصيل |
|---|---|
| الملفات المتأثرة | `index.html` (عنصر اختيار)، `app.mjs` (جمع المدخلات، توقيع التغيّر، الاسترجاع) |
| السبب | المحرك يدعم الآن `rect` و`l` و`u`، ولا توجد حالياً طريقة للمستخدم لطلب غير المستطيل |
| الـContract المطلوب (مدخل) | حقل اختياري `shape` في مدخلات الأرض، قيمه محصورة في مفاتيح `SHAPES` المُصدَّرة من المحرك. غيابه أو قيمة غير معروفة = `rect` |
| ما يستهلكه من المخرجات | `model.shape` (الشكل المنفَّذ فعلياً)، `model.shapeFallback` (هل رُجع للمستطيل)، `model.warnings` (نص سبب الرجوع) |
| شرط القبول | إذا `shapeFallback === true` يجب أن يرى المستخدم أن الشكل المطلوب لم يُنفَّذ، لا أن يظن أن المستطيل هو ما طلبه |
| ملاحظة | قائمة الخيارات يجب أن تُبنى من `SHAPES` المُصدَّرة، لا أن تُكتب يدوياً، حتى لا يعرض العرض شكلاً غير مدعوم |

## IR-2 — رسم الفناء في المخطط 2D

| البند | التفصيل |
|---|---|
| الملف المتأثر | `plan-view.mjs` |
| السبب | في شكل U يقع الفناء داخل مستطيل `model.building`. الرسم الحالي يملأ كامل مستطيل المبنى بلون الكتلة المبنية، فيظهر الفناء كأنه مبنى |
| الـContract المطلوب (مخرج) | `model.courtyards: Array<{ name, x, y, w, h }>` بنفس نظام إحداثيات الغرف (متر، x شرق، y شمال). مصفوفة فارغة لغير U |
| ما يستهلكه | `model.courtyards` فقط |
| شرط القبول | الفناء يظهر مميزاً عن الكتلة المبنية وعن الممرات والمساحات غير الموزعة |
| ضمان من المحرك | لا تتداخل أي غرفة أو ممر مع أي فناء (مغطى باختبار) |

## IR-3 — تمييز الفناء في العرض 3D

| البند | التفصيل |
|---|---|
| الملف المتأثر | `viewer3d.mjs` |
| السبب | نفس سبب IR-2: بلاطة الأرضية تُرسم على كامل `model.building` |
| الـContract المطلوب | نفس حقل IR-2 |
| ما يستهلكه | `model.courtyards` |
| شرط القبول | الفناء لا يظهر كأرضية داخلية مسقوفة؛ وخيار «إظهار السقف» لا يغطيه |
| ملاحظة | السقف الحالي مستطيل واحد بحجم `model.building`. تغطية الفناء بالسقف قرار عرض يعود للمطور الثاني |

## IR-4 — الكميات (للعلم، ليس تعديلاً على ملف عرض)

`quantities(model).footprint` أصبحت تستثني مساحة الفناء، وأضيف `quantities(model).courtyard`. أي عرض يعتمد على `footprint` سيعرض الرقم الصحيح تلقائياً. إن أراد العرض إظهار مساحة الفناء منفصلة فالحقل متاح.

## ما لم يتغيّر في المخرجات (توافق خلفي)

- المستطيل يحتفظ بنفس معرّفات الممرات القديمة (`spine`، `branch-…`).
- نفس بنية `rooms` و`corridors` و`walls` و`openings` و`reserves` و`links`.
- اختبارات المشروع الأصلية الـ12 نجحت دون تعديل عليها.
